# Ежедневная сводка для Telegram-группы «Дикая Рыбалка»

Каждый день в 7:30 по Calgary бот присылает в группу погоду, топ-3 наших точек по оценке клёва и по одной новости об Альберте и о Канаде (с кратким описанием, когда его удалось получить).
Работает на GitHub Actions бесплатно, без компьютера и без ИИ. К карте (`fishmap`) отношения не имеет.

- `digest.mjs`: скрипт (погода Open-Meteo, новости Google News RSS, отправка через Telegram Bot API).
- `filters.mjs`: фильтры новостей, дедупликация, проверка описаний (без сети).
- `fishscore.mjs`: порт формулы клёва из `app.js`.
- `test/`: тесты (`node --test "news-bot/test/*.test.mjs"` из корня репозитория); на GitHub их запускает `../.github/workflows/news-bot-tests.yml`.
- `../.github/workflows/daily-digest.yml`: расписание и ручной запуск.

## Секреты (Settings, Secrets and variables, Actions)

- `TELEGRAM_BOT_TOKEN`: токен бота от @BotFather.
- `SUPABASE_GROUP_CODE`: код группы из приложения карты. Нужен, чтобы читать точки из базы. Без него берутся только точки из `spots.json`.
- `TELEGRAM_CHAT_ID`: ID чата. Для теста ID личного чата, для боевой работы ID группы. Переключение: заменить значение секрета.

Токен и ID в репозитории не хранятся. Репозиторий публичный, логи запусков тоже публичные, поэтому в них ничего секретного не печатается.

## Ручной запуск

Actions, daily-digest, Run workflow.
- `dry_run` включён: сообщение только печатается в логе, в Telegram не уходит.
- `dry_run` выключен: сообщение реально уходит в чат из `TELEGRAM_CHAT_ID`.
- `save_state` для проверок включать не нужно: тогда тестовая отправка не считается дневной и не «сжигает» новости.
- `selftest`: проверяет только сохранение и чтение кэша, ничего не отправляет.
В пробном запуске названия точек скрыты (логи публичные).

## Как работает

- «Топ 3 точки»: точки читаются из базы карты (Supabase, только чтение), оценка считается той же формулой, что в приложении (`fishscore.mjs`, порт из `app.js`; если формула в `app.js` изменится, обновить и здесь). Сезон (лето или зима) выбирается по режиму «Авто», показываются три лучшие точки. Зимой лёд оценивается только по погоде.
- Описание новости: ссылка Google News раскрывается до настоящей статьи, из неё берётся `og:description`. Обрезанные описания сокращаются до целого предложения. Если получить описание не удалось, уходит только заголовок.
- Раздел «Альберта» (новости за 21 день) и «Канада» (за 14 дней). Берётся самая свежая подходящая новость, которой ещё не было (в том числе пересказ той же истории другим изданием). Регион проверяется по заголовку: в «Канаде» в заголовке должно быть канадское место (канадские сайты перепечатывают новости США, одного канадского источника мало); в «Альберте» место Альберты в заголовке или местное издание Альберты. Одноимённые места в других странах (Victoria, Ottawa, Airdrie и т. п.) без канадского источника не проходят. Промысел, аквакультура, морские промыслы (креветки, моллюски), развлекательные сайты США, путевые заметки, происшествия и биржевые новости отсекаются (`BLOCK`, `TRAVEL`). Описание берётся со страницы, только если страница про эту же новость и текст не шаблонный.
- Если свежей новости нет, раздел пропускается. Если нет точек на текущий сезон, блок «Топ точек» тихо пропадает.
- Текст про погоду и лёд собирается по правилам, как режим «Авто» в приложении (зима, если средняя температура за 5 прошлых и 2 дня прогноза не выше минус 5). Это не оценка толщины льда. Фраза про лёд согласована с режимом блока точек: после долгих морозов и оттепели пишется «лёд мог остаться, но ненадёжен», а не «льда нет».
- Память об отправленных новостях хранится в кэше GitHub Actions (`news-bot/state.json`). Если кэш потеряется, возможен повтор вчерашней новости.
- С ноября 2026 Альберта живёт на постоянном UTC-6: 7:30 по Calgary = 13:30 UTC. Запуск в 14:30 UTC (8:30) это повтор на случай сбоя; он не отправит второй раз, если дата уже сохранена. Скрипт использует фиксированный пояс UTC-6 (константа `TZ`), потому что tzdata на раннере GitHub может не знать об этом изменении. Если правила времени в Альберте изменятся, константу нужно поправить.
- Отправка устойчива к сбоям: повторы при обрыве связи, 429 и 5xx; если группа стала супергруппой, сообщение уходит в новый чат, а в запуске появляется предупреждение с просьбой обновить `TELEGRAM_CHAT_ID`. На всю работу отведено 150 секунд.
- Если какой-то блок не удалось получить (погода, точки, новости), сводка всё равно уходит, а запуск помечается ошибкой, чтобы GitHub прислал письмо.
